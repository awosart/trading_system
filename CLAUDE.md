# КОНТЕКСТ ПРОЕКТА

Ты — senior Python-разработчик с опытом в quantitative trading infrastructure.
Мы строим модульную торговую систему `trading_system` с нуля.

## Ключевая архитектурная идея

Стратегия НЕ управляет деньгами. Стратегия отдаёт сигнал с оценкой качества.
Размер позиции, стоп и допуск к торговле определяют отдельные модули.

    Market Data → Features → Regime → Strategy Selector → Entry Engine
      → Signal(quality, direction, invalidation)
      → Risk Engine (sizing) → Prop Guard (hard limits) → Execution → Portfolio → Analytics

Разделение обязательное:
- Entry Engine и Exit Engine — независимые библиотеки, комбинируются N×M.
- Risk Engine ничего не знает про индикаторы, только про Signal и состояние портфеля.
- Prop Guard — последний слой, имеет право veto на любой ордер.

## Стек

- Python 3.12 (`requires-python = ">=3.12,<3.13"`), менеджер зависимостей `uv`
- pydantic v2 — все схемы и конфиги
- polars — единственный dataframe-слой. pandas НЕ используется и не входит в
  зависимости (решение P02). Индекса нет: гарантии времени лежат на колонке
  `timestamp` внутри `OHLCVFrame`, а не на DatetimeIndex.
- DuckDB + Parquet — хранение рыночных данных и результатов. Чтение диапазонов
  идёт через polars `scan_parquet`, DuckDB — слой агрегирующих SQL-запросов
  (`coverage`, `query`), т.к. `.pl()` тянет pyarrow ради одной конвертации.
- pytest + pytest-cov + hypothesis — тесты
- ruff (lint+format), mypy --strict — качество
- structlog — логирование (JSON в файл, human-readable в консоль)
- typer — CLI
- streamlit — UI (только в конце)

## Жёсткие конвенции

1. **Время**: все timestamp — tz-aware UTC. Локальное время только на слое отображения.
   Timestamp бара = время ОТКРЫТИЯ бара. Это документируется в docstring каждого loader'а.
2. **No lookahead**: на баре t стратегия видит закрытые бары ≤ t. Исполнение — не раньше
   открытия бара t+1 (либо по модели исполнения, но никогда не по close(t)).
3. **Деньги**: денежные величины и учёт — `decimal.Decimal` или int в минимальных единицах.
   Цены и индикаторы — float. Не смешивать.
4. **Никаких глобальных состояний.** Всё через явные зависимости в конструкторе (DI).
5. **Типизация обязательна.** mypy --strict должен проходить.
6. **Каждый публичный модуль имеет тесты.** Без тестов задача не считается выполненной.
7. **Никакой магии в конфигах**: конфиг — pydantic-модель, а не dict. Ошибка конфига падает
   на старте, а не в рантайме.
8. Docstrings — Google style, на английском. Комментарии по делу, а не пересказ кода.

## Решения P03 (feature-слой)

- **Ichimoku без chikou.** В точке отрисовки chikou — это close через `displacement`
  баров вперёд; причинной формы нет. Нужна та же информация — сравнивай
  `close[t]` с `close[t - displacement]` напрямую.
- **Пивоты публикуются на баре подтверждения**, а не на баре события. Фрактал на
  баре `c` виден только с `c + lookback`; `Swing` несёт оба индекса.
- **Warmup единый по всем каналам индикатора.** MACD-линия арифметически доступна
  раньше сигнала, но публикуются все каналы вместе: строка либо целиком пригодна,
  либо не выдаётся. `warmup` = число ведущих баров без значения.
- **Многоканальные индикаторы — `MultiOutputIndicator`** с `compute_frame() -> DataFrame`.
  Протокол `Indicator` с `.compute() -> Series` остаётся для одноканальных.
- **pandas_ta не используется** даже как эталон для тестов — он тянет pandas.
  Эталон — формулы, посчитанные вручную в тестах.
- **`typical_price` подстроен под оптимизацию polars**: polars компилирует `x / 3`
  в `x * (1/3)`, и расхождение в последнем бите переворачивает строгое сравнение
  соседних typical price в MFI. Стережёт parity-тест: если polars перестанет так
  делать, он упадёт.

Общий контракт слоя: каждый индикатор существует в двух режимах (векторный polars
и инкрементальный state machine), они обязаны совпадать до 1e-9 —
`BaseIndicator.verify_parity`, который тесты гоняют по всему реестру. Пропуски —
polars null, никогда NaN и никогда forward-fill.

## Решения P04 (strategy schema)

- **`Condition` — discriminated union**, а не «умное» объединение. Каждый узел
  (`LeafCondition`/`AllOf`/`AnyOf`/`Not`) несёт литеральное поле `type`; без него
  pydantic не может однозначно и быстро выбрать вариант в рекурсивном дереве, а
  JSON Schema получает чистый `oneOf` вместо расплывчатого `anyOf`.
- **`exit_ref` и уникальность `id` проверяются только если передан внешний
  реестр.** Exit DB ещё не существует, поэтому `validate_spec`/`validate_paths`
  по умолчанию эти проверки пропускают (`known_exit_ids=None`), а не подставляют
  фиктивный список. Когда появится Exit Engine — прокинуть его реестр явным
  аргументом, а не хардкодить здесь.
- **`RANGE` + breakout-триггер — это WARNING, а не ERROR.** Совпадение
  `cross_above`/`cross_below` с режимом `RANGE` — эвристика, не доказательство
  противоречия (тот же оператор бывает и в отбое от границы диапазона), поэтому
  решение остаётся за человеком.

## Правила работы (анти-паттерны — НЕ делать)

- Не писать «на будущее». Пишем минимум, который проходит Definition of Done.
- Не добавлять AI/ML/автоматизацию, пока не работает детерминированное ядро.
- Не добавлять 1000 стратегий. Сначала 1 стратегия → 1 бэктест → анализ → улучшение.
- Не оптимизировать параметры до того, как готов walk-forward. Иначе это overfit.
- Не использовать `try/except: pass`. Ошибки логируются или пробрасываются.
- Не хардкодить символы, таймфреймы, размеры счёта. Всё в конфиг.
